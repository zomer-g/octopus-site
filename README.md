# התמנון – אתר (octopus.org.il)

האתר נבנה מחדש מהוורדפרס הישן, בלי וורדפרס. התוכן נשמר **במבנה של וורדפרס**, כך שאפשר לייבא ולייצא אותו בין האתר הזה לכל אתר וורדפרס.

- האתר: [Astro](https://astro.build) בונה ממנו דפים סטטיים.
- השרת: Node, עם ממשק ניהול בכתובת `/admin`.
- האירוח: אפליקציית Docker בשם `octopus-site` ב-xhostd.

## ממשק הניהול (`/admin`)

- **התחברות** עם חשבון Google. מורשים: הכתובות במשתנה `ADMIN_EMAILS`, וכל מי שנוסף במסך "עורכים".
- **פוסטים ועמודים**: המצבים כמו בוורדפרס (פורסם, טיוטה, ממתין לאישור, פרטי, פח). נשמרות כל הגרסאות, ואפשר לחזור לנוסח שיובא.
- **שינוי כתובת או תאריך** נרשם כמו בוורדפרס (`_wp_old_slug`, `_wp_old_date`), והכתובת הישנה מפנה לחדשה.
- **בלוקים של וורדפרס** נשמרים כמו שהם בעריכה. בלוקים דינמיים, כמו רשימות פוסטים, מוצגים בעורך כמלבן שאי אפשר לערוך בטעות.
- **"רשימת פוסטים"** בעורך מוסיפה בלוק `latest-posts` של וורדפרס.
- **ספריית המדיה**: קבצים מועלים ל-`/wp-content/uploads/YYYY/MM/`, כמו בוורדפרס.
- **תפריט**: נשמר כתפריט וורדפרס (`nav_menu_item`).
- **ייבוא וייצוא** (WXR 1.2, הפורמט של "כלים ← ייצוא" בוורדפרס):
  - **ייצוא**: כל התוכן, כולל טיוטות, מדיה, תפריטים, מטא-דאטה ותגובות. וורדפרס מייבא אותו דרך "כלים ← ייבוא ← WordPress".
  - **ייבוא – הוספה (APPEND)**: מוסיף רק מה שעוד לא קיים. מזהים שמתנגשים ממוספרים מחדש, וההפניות אליהם (תמונה ראשית, הורה, קטגוריות בתוך בלוקים) מתעדכנות.
  - **ייבוא – החלפה (REPLACE)**: מחליף את כל התוכן. לפני כן נשמר גיבוי מלא, שאפשר להוריד מאותו מסך.
  - **מדיה מאתר אחר**: הקבצים יורדים לאחסון של האתר, והקישורים בתוכן מועברים אליו.
  - **חבילת ZIP**: קובץ XML אחד וקבצים בתיקייה `wp-content/uploads/YYYY/MM/`. הקבצים נשמרים באחסון בנתיב שלהם, והפריטים מיובאים כרגיל. כך מעלים טיוטות עם מסמכים מצורפים: כל פוסט בסטטוס `draft`, וכל קובץ כפריט `attachment` עם `_wp_attached_file` ו-`attachment_url` בכתובת `https://octopus.org.il/wp-content/uploads/...`.
- **פרסום**: האתר נבנה מחדש בשרת (בערך דקה) ומוחלף רק אם הבנייה הצליחה.

## איך זה בנוי

| מקום | מה יש בו |
|---|---|
| `wp_items`, `wp_terms`, `wp_authors` ב-Postgres | רשומה לכל פריט WXR (פוסט, עמוד, קובץ, פריט תפריט…), עם כל השדות וה-postmeta |
| `wp_item_history` | כל גרסה שנשמרה |
| `archive/wxr/octopus-2026-09-19.xml` | הייצוא המקורי מוורדפרס. נטען אוטומטית כשמסד הנתונים ריק. |
| `archive/rendered.json` | ה-HTML שוורדפרס הציג לכל פריט. משמש כל עוד הפריט לא נערך. |
| `media/wp-content/uploads` | הקבצים מהאתר הישן (בתוך ה-image) |
| אחסון הקבצים (S3) | קבצים שהועלו או יובאו, בגיבויים וב-`wp-content/uploads/...` |
| `server/wxr.js` | קריאה וכתיבה של קובצי WXR |
| `server/store.js` | שמירה, ייבוא (הוספה והחלפה) וייצוא |
| `server/generate.js`, `server/render.js` | הפיכת הנתונים לדפי האתר: כתובות, קטגוריות, תפריט, הפניות, ורינדור תוכן וורדפרס |
| `server/builder.js` | בנייה מחדש ברקע והחלפת האתר המוגש |
| `server/admin/` | ממשק הניהול |
| `site.config.json` | הגדרות האתר: קובץ הבסיס, כתובת האתר, עמוד הבית, תפריט ראשי |

`src/content` ו-`src/data` נוצרים אוטומטית, ולא נשמרים ב-git.

## פיתוח מקומי

```bash
npm install
npm run build                               # מייצר את התוכן מקובץ ה-WXR ובונה את dist
node --env-file=.env.local server/index.js  # השרת המלא עם ממשק הניהול
```

`.env.local` לבדיקה מקומית, לא נשמר ב-git:

```
PORT=3100
LOCAL_PGLITE=.pglite
DEV_ADMIN_EMAIL=you@example.com
ADMIN_EMAILS=you@example.com
```

`DEV_ADMIN_EMAIL` מדלג על ההתחברות. הוא פעיל רק כשאין `DATABASE_URL`, ולכן אף פעם לא ב-xhostd.

## הריפו הפומבי

הריפו הפומבי (https://github.com/zomer-g/octopus-site) מתעדכן בפקודה `bash tools/publish-public.sh "הודעה"`.
הוא מקבל עותק של הקוד בלי ייצוא הוורדפרס המלא: בייצוא המלא יש טיוטות, פוסטים פרטיים, פניות מטופס יצירת הקשר, כתובות מייל וכתובות IP.
במקומו נכלל `archive/wxr/octopus-public.xml`, שמכיל רק את מה שמוצג באתר. הוא נוצר בפקודה `node tools/make-public-wxr.mjs <מלא.xml> <פומבי.xml>`.
הריפו הפומבי מתנהל עם היסטוריה נפרדת, כך שהקובץ המלא לא מופיע בו גם לא בגרסאות קודמות.

## להקים אתר אחר באותה שיטה

1. שמים את קובץ הייצוא של האתר ב-`archive/wxr/`.
2. מעדכנים את `site.config.json`: `baseline`, `siteUrl` ו-`frontPageId`.
3. מוחקים את `archive/rendered.json`. בלעדיו כל התוכן יוצג דרך הרינדור של השרת.
4. פורסים לאפליקציה חדשה. בהפעלה הראשונה התוכן נטען מהקובץ.

## עדכון הקוד

```bash
git push xhost HEAD:master   # ואחר כך deploy לאפליקציה octopus-site, ערוץ prod
```
